# Архитектура Vibe Viewer

## Поток открытия файла

1. `MainWindow` получает путь от дерева файлов или диалога.
2. `ViewerRegistry` опрашивает обработчики по приоритету.
3. Первый подходящий класс создаётся и кэшируется в `QStackedWidget`.
4. Предыдущий обработчик получает `unload()` и освобождает файл или медиаресурс.
5. Ошибка декодирования не завершает программу: файл открывается через `BinaryViewer`.

Реестр учитывает составные расширения, например `.tar.gz`. Обработчики с более высоким
приоритетом разрешают неоднозначности: EPUB является ZIP-контейнером, но открывается как
электронная книга; DOCX является ZIP-контейнером, но открывается как документ.

Расширение определяет первый специализированный обработчик, но не гарантирует успешный
разбор повреждённого файла. Если обработчик возвращает `ViewerError`, главное окно
показывает понятную ошибку и безопасный двоичный предпросмотр. Точный перечень маршрутов
и уровней поддержки хранится в [`FORMATS.md`](FORMATS.md).

## Границы приложения

Все обработчики работают внутри процесса Vibe Viewer. В рабочем коде запрещены
`subprocess`, `os.system`, `QProcess`, `xdg-open` и вызовы консольных конвертеров.
Python-пакеты из `requirements.txt` являются библиотеками и импортируются напрямую.
Qt Multimedia использует поставляемый с Qt backend FFmpeg как библиотеку, а не запускает
программу `ffmpeg`.

Контейнер, Doxygen и установочный скрипт относятся к сборке и разработке, а не к пути
просмотра пользовательского файла. Они не вызываются приложением во время работы.

## Добавление нового формата

Создайте класс в `src/vibe_viewer/viewers/`:

```python
from pathlib import Path
from vibe_viewer.viewers.base import BaseViewer


class MyViewer(BaseViewer):
    name = "My format"
    category = "Special"
    priority = 50
    extensions = (".myf",)

    def load_file(self, path: Path) -> None:
        # Заполнить собственные Qt-виджеты.
        ...
```

Зарегистрируйте класс в `register_default_viewers()` и добавьте тест. Главное окно,
диалог форматов и счётчик расширений обновятся автоматически.

## Правила обработчиков

- Не использовать `subprocess`, `os.system`, `xdg-open` и внешние приложения.
- Не читать большой файл полностью, если достаточно ограниченного предпросмотра.
- Архивы по умолчанию только индексируются и не распаковываются.
- Pickle и другие форматы с исполнением кода не загружаются.
- Для необязательной библиотеки импорт выполнять внутри `load_file()`.
- Все открытые документы, базы данных и медиаресурсы закрывать в `unload()`.
- Заявлять расширение только при наличии тестового образца или ручной проверки.

Сложные форматы объединены по способу представления: временная шкала для субтитров,
таблица записей для плейлистов и сетевых дампов, XML/координатная сводка для геоданных,
структура сцены для 3D и безопасные заголовки/секции для исполняемых файлов. Обработчики
никогда не исполняют содержимое просматриваемого файла.

## Ограничения

- Отображение DOCX/PPTX/ODF передаёт содержимое, но не гарантирует пиксельное совпадение
  с Microsoft Office или LibreOffice.
- Старые DOC/PPT имеют экспериментальный режим извлечения текстовых фрагментов.
- Реальная поддержка аудио- и видеокодеков зависит от backend-модуля Qt Multimedia/FFmpeg
  для конкретной платформы.
- Бинарный режим доступен для любого неизвестного формата, но не входит в счётчик.
